# Nebula 功能对照

本项目以 `Kuddev/nebula` 提交 `74f19d8`（v1.2.0，2026-08-21 获取）作为行为对照。Nebula 使用 GPL-3.0；本项目只分析公开功能和交互，并把其 GPUI 界面当作“设计图纸”做数值对标（间距、圆角、阴影、动效时长、配色 token），全部在 React/CSS 中独立实现，不复制其 Rust 源码、图片或其他 GPL 资产。

## 部分覆盖

| 能力 | 当前限制 |
| --- | --- |
| 崩溃恢复 | 有启动跟踪、恢复隔离和标签快照；尚无 Nebula 的完整诊断界面与输入延迟探针 |
| SSH 高级能力 | 系统 OpenSSH 可继承用户配置；应用内尚无完整代理、跳板、多种认证和 keepalive 设置页 |
| WSL | 能发现并启动发行版、文件面板跟随 WSL 路径、命令补全走 WSL 目录扫描；系统目录选择器中尚无专用 WSL 快捷入口 |
| 快捷键 | 已实现可录制自定义键位页（命令面板、新终端、分屏、全局快速终端、打开设置，可一键恢复默认）；尚无分组可搜索的键位列表与冲突检测 |
| GPU 界面壳 | 当前 Electron/Chromium 默认使用 GPU 合成且只有一套 Nebula 风格界面；没有改用 Rust + GPUI，也没有保留 `--legacy-shell` 双壳。对本项目规模，迁移会重写 xterm.js、node-pty、窗口/托盘/剪贴板与自动化测试，现阶段收益不足 |
| Runtime 控制与编排 | 已有 Provider 的 start/stop、真实 PTY 进程与退出码生命周期；尚无 `nebula ctl orchestrate` 对应的强类型工作流、命名 agent、控制键命令和公开 Runtime schema/API |
| 托管 agent worktree | 现有 AI 会话分叉会创建新终端/会话，但尚无稳定分支/路径身份、事务式 worktree 创建与失败回滚 |
| 内置制表符字形 | xterm.js 能渲染终端常见制表/边框字符；尚无 Nebula 那种脱离字体、按几何路径绘制的专用字形层 |

## 暂缓项目

- 加密工作区导出、恢复预览、冲突处理和回滚。
- 应用内更新检查与发布通道。
- 独立图片标签查看器与字体文件导入。
- DeepSeek Harness 的完整插件管理和协议仍在变化的高级设置。

这些项目不适合通过移植 Nebula 源码完成。后续应按本项目的 Provider、Electron IPC 和 React 组件边界独立实现，并为配置迁移和恢复流程增加专门测试。
